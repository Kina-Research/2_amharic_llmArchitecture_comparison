# Project Cleanup & Audit Report (2026-11-07)

## 1. Critical finding: results are simulated

All 15 run groups in `results/raw/` were generated by `scripts/populate_benchmark_results.py`, not by
training. Evidence:
- `results/raw/summarization/*/lora/seed42/predictions.csv`: 5 hand-written references repeated 100×;
  predictions are `"[<Architecture>] <reference>"`. Per-document ROUGE/BERTScore values are random draws
  that do not correspond to the texts.
- Metric values match the hard-coded targets in the script; ECE is overwritten with a target value.
- `run_info.json` contains no `environment` block (real runs via `src/training/*` always write one).

Actions taken: the files were **kept unchanged** (they are the user's research artefacts), but
- `README.md` now carries a CAUTION notice above the results tables;
- the populate script's docstring, runtime output and a `warnings.warn` now say SIMULATED;
- `generate_results.py` (via `src/evaluation/report.py`) now lists runs lacking a captured environment
  as "probably SIMULATED" in `results/tables/STATUS.md`.

**The tables and figures in README must not be reported as findings until real runs replace them.**

## 6. Dataset

**No dataset changes were made, and no data was added.**
- `data/processed/` does not exist in this workspace. The data is downloaded from Hugging Face by
  `scripts/prepare_data.py`, which needs network access and `datasets`.
- The existing pipeline already does the quality steps the task asks for: NFC normalisation, URL/mention/
  HTML-entity removal, length and Ethiopic-ratio filtering, dropping conflicting-label duplicates,
  normalised-key deduplication, stratified split, and cross-split leakage checks with a provenance
  manifest and SHA-256 checksums.
- It already uses all official AfriSenti-amh splits and all XL-Sum-am train/validation pairs
  (`train_max: null`). Adding other corpora would change the research design, so it was not done.
